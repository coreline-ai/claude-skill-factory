## 3. Architecture Decisions

| 결정 | 선택 | 근거 |
|---|---|---|
| sdist에 외부 파일 포함 | **symlink** (`tools/claude-skill-factory/LICENSE -> ../../LICENSE` 등) | setuptools가 symlink는 추적 가능; 평탄화는 큰 변경 |
| 사용자 룰 파일 포맷 | JSON (`{"rules":[{...SkillRule...}]}`) | toml은 다중 dict 표현 번거로움, json은 stdlib 충분 |
| 사용자 룰 위치 | `<claude_home>/skill-factory/user_rules.json` | user scope 표준 디렉터리 재사용 |
| rotation 전략 | size + age 둘 중 하나 임계 도달 시 `<path>.YYYYMMDDHHMMSS.bak.jsonl` 생성 | 안전 (삭제 안 함) + reversible |
| logging 모듈 | stdlib `logging` (외부 의존 없음) | 7원칙 Local-first/Deterministic |
| verify 검증 항목 | 6 frontmatter 필수 필드 + Base 8 섹션 + 1536자 한계 + name kebab-case | skill_template_spec.md §2~§4 SSOT 기준 |
| 충돌 감지 시점 | promote 사전 + doctor 후사 | 사전 차단 우선, 사후 감지로 직접 편집 케이스 커버 |
| exit code 표 | 0=ok, 1=health/state fail, 2=usage error (typer 기본), 3=conflict, 4=permission | typer 1/2 관례 + 의미 분리 |
| `--verbose` 작용 범위 | 모든 명령 (typer callback) | 일관성 |
| `--no-auto-invoke` default | False (자동 활성화 유지) | 기본 UX 유지 |
| 충돌 감지 후 동작 | `--overwrite` 없이는 PermissionError(exit 3) | H2 패턴 재사용 |
| 사용자 룰 파일 부재 | 빈 list 반환 (silent) | "있으면 추가, 없어도 OK" |

### 3.1 신규 모듈 (4개)

```python
# skill_factory/logging_setup.py
def setup_logger(verbose: bool = False) -> logging.Logger: ...
def get_logger() -> logging.Logger: ...

# skill_factory/user_rules.py
def load_user_rules(home: Path | None = None) -> list[SkillRule]: ...
USER_RULES_FILENAME = "user_rules.json"

# skill_factory/rotation.py
@dataclass(frozen=True)
class RotationResult:
    path: Path
    rotated_to: Path | None  # None if no rotation needed
    reason: str | None       # "size" / "age" / None

def rotate_jsonl(path: Path, *, max_size_mb: int = 50, max_age_days: int = 30) -> RotationResult: ...

# skill_factory/verifier.py
@dataclass(frozen=True)
class VerifyResult:
    ok: bool
    errors: list[str]
    warnings: list[str]

def verify_skill_md(path: Path) -> VerifyResult: ...
```

### 3.2 수정 파일

| 파일 | 변경 |
|---|---|
| `pyproject.toml` | `license = { file = "LICENSE" }`, `readme = "README.md"` (symlink 경유) |
| `MANIFEST.in` | `include LICENSE README.md CHANGELOG.md` 등 (이번엔 진짜 포함됨) |
| `cli.py` | 3 신규 명령 (uninstall/rotate/verify) + 4 기존 명령 보강 + `--verbose` callback + exit code 정리 |
| `rules.py` | RULES = built-in + user 합쳐서 노출 (또는 함수 분리) |
| `templating.py` | `disable_model_invocation: bool = False` 인자 |
| `templates/SKILL.md.j2` | `disable-model-invocation` 값 변수화 |
| `__init__.py` | 신규 모듈 re-export |

## 6. Risks

| 위험 | 영향 | 완화 |
|---|---|---|
| symlink가 setuptools에서 깨질 수 있음 | 중간 | Phase 1 마지막에 격리 venv smoke 통해 즉시 검증 |
| cli.py 동시 변경으로 conflict | 높음 | cli.py는 단일 agent에 일임, 다른 모듈은 다른 agent |
| user_rules.json 잘못된 schema에 graceful 실패 미흡 | 중간 | TC-4.3로 명시적 회귀 |
| rotate가 race로 데이터 일부 유실 | 중간 | fcntl로 보호 + atomic move |
| logging 도입으로 기존 print 출력 깨짐 | 낮음 | 단계적 도입 (Phase 5 하단부) + 기존 stdout 메시지 유지 |
| 1536자 cap 검증이 multibyte 문자에서 부정확 | 낮음 | bytes 길이 아닌 문자 길이로 명시 |
| `--no-auto-invoke` 추가로 Jinja `default` 필터 의존 | 낮음 | StrictUndefined와 충돌 없는지 명시 테스트 |

## 7. Execution Rules

1. Phase 1, 2, 3, 4, 5는 가능한 범위 내에서 병렬 실행한다.
2. cli.py 변경은 단일 agent (Phase 2/3/4/5 cli 부분 통합)에 일임해 충돌 회피.
3. 각 Phase의 모든 Test Cases 통과 후에만 Phase 6 통합 진행.
4. Phase 6 도중 회귀 발견 시 해당 Phase 재작업 (다음 Phase 진행 X).
5. AGENTS.md 정책: git push / PyPI upload는 본 계획 범위 밖.
6. dev-plan 체크박스는 사용자가 직접 갱신.
