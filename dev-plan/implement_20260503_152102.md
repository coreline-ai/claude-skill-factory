# Implementation Plan: Claude Skill Factory v0.1.0

> Codex Prompt Skill Factory(`codex-autocreator-skill`)를 Claude Code 전용으로 재구현한다. Codex 종속(hooks.json·.codex/·config.toml flag)은 모두 제거하고 Claude Code 사양(`.claude/settings.json`·`.claude/skills/`·SKILL.md frontmatter)으로 치환하되, 제품 원칙·이식 가능 코어 로직(rules/similarity/quality/spec_compiler 등)은 그대로 계승한다.
> Generated: 2026-05-03
> Project: claude-skill-factory

## 1. Context (배경)

### 1.1 Why (왜 필요한가)

- 참조 프로젝트 `codex-autocreator-skill`은 Codex 전용으로 설계되어 Claude Code 사용자가 그대로 쓸 수 없다.
- Hook 이벤트명(`UserPromptSubmit`/`Stop`/`PostToolUse`)은 우연히 동일하지만, **설정 파일 포맷·payload 스키마·Skill 위치·SKILL.md frontmatter 사양이 모두 다르다**.
- 최근 코드베이스(`similarity.py` 264 → 570 lines 등)는 SSOT 문서(`docs/CLAUDE_REF.md`)와 어긋나 있어 단순 fork 후 부분 수정으로는 정합성을 잡기 어렵다.
- 따라서 Claude Code 사양 우선의 **신규 패키지**를 깨끗하게 구축하고, 이식 가능한 도메인 로직만 선택적으로 가져온다.

### 1.2 Current State (현재 상태)

- `claude-skill-factory/` 저장소에는 `docs/CLAUDE_REF.md` (참조 인벤토리, 555줄)만 존재. 코드 0줄.
- `codex-autocreator-skill/`은 Codex 종속 코드 ~3045줄 + 테스트 632줄 + 문서 ~2200줄 (read-only 참조).
- Claude Code 사양은 외부 문서로 확인됨:
  - Hook 위치: `<repo>/.claude/settings.json` 또는 `~/.claude/settings.json`
  - Hook 스키마(3단 중첩): `{ "hooks": { "<EventName>": [ { "matcher": "*", "hooks": [ { "type": "command", "command": "...", "async": false } ] } ] } }`
  - Hook stdin 공통 키: `session_id`, `transcript_path`, `cwd`, `permission_mode`, `hook_event_name`
  - Tool 이벤트 추가 키: `tool_name` (Bash/Edit/Write/Read/Grep/Glob/WebFetch/WebSearch/Agent/AskUserQuestion 등), `tool_input`, `tool_use_id`
  - Skill 위치: `<repo>/.claude/skills/<name>/SKILL.md` 또는 `~/.claude/skills/<name>/SKILL.md`
  - SKILL.md frontmatter 신규 필드: `when_to_use`, `allowed-tools`, `disable-model-invocation`, `user-invocable`, `model`, `effort`, `context`, `agent`, `paths`, `argument-hint`, `arguments`, `shell`

### 1.3 Target State (목표 상태)

- `pip install claude-skill-factory` 또는 `pipx install claude-skill-factory` 후 `claude-skill-factory` CLI가 동작.
- Golden Path: `init` → (Claude Code 사용 → hook 자동 수집) → `inbox` → `promote <name>` → `doctor` 5명령으로 완결.
- 모든 데이터 산출물이 `.claude/` 네임스페이스 하위에 저장 (`~/.claude/skill-factory/`, `<repo>/.claude/prompt-history/`, `<repo>/.claude/skill-suggestions/`, `<repo>/.claude/skills/`).
- 생성된 Skill은 Claude Code가 즉시 인식 가능한 SKILL.md 포맷 (frontmatter 검증 통과).
- 9개 테스트 파일이 모두 통과하며 secret redaction 회귀 테스트 보존.
- 참조 프로젝트 발견 결함(C1 redaction 갭, C2 hooks 덮어쓰기, H1 `--yes` 무동작, H2 ignored→approved 우회, H3 inbox TTY 행, H4 `--project` 비대칭, M7 generalization_safety 점수 무력화)을 모두 해결한 상태.

### 1.4 Scope Boundary (범위)

- **In scope**:
  - Claude Code 사양 100% 준수의 신규 Python 패키지 (`tools/claude-skill-factory/`)

  - 참조 프로젝트의 알려진 결함 7건(C1·C2·H1·H2·H3·H4·M7) 동시 수정
  - AGENTS.md, README.md, docs/dev_doc.md, docs/skill_template_spec.md 신규 작성
- **Out of scope**:
  - Codex 호환 모드 (완전 결별)

## 2. Architecture Overview (아키텍처)

### 2.1 Design Diagram

```text
┌───────────────────────────────────────────────────────────────────────┐
│                    Claude Code (외부, 수정 불가)                       │
│  UserPromptSubmit / Stop / PostToolUse 이벤트 → stdin JSON payload     │
└──────────────────────────┬───────────────────────────────────────────┘
                           │
                           ▼  (claude-skill-factory hook-* --project)
┌───────────────────────────────────────────────────────────────────────┐
│  CLI 진입점 (skill_factory/cli.py)                                     │
│  ├─ Golden Path: init / inbox / promote / dashboard / doctor          │
│  ├─ Analysis: scan / report / preview / analytics                     │
│  ├─ Approval: approve / ignore / unignore / review / enrich / create  │
│  └─ Hidden: hook-user-prompt / hook-turn-stop / hook-post-tool-use    │
└────┬──────────────────────────────────────────────────────────────────┘
     │
     ├──► hook_handlers.py (stdin → redact → normalize → jsonl)
     │
     ├──► storage.py (Paths · scope routing · IO)
     │      ├─ user scope:  ~/.claude/{prompt-history, skill-factory, skills}/
     │      └─ project:     <repo>/.claude/{prompt-history, skill-suggestions, skills}/
     │
     ├──► [pipeline] rules.classify_prompt
     │              + similarity.find_similarity_clusters
     │              + enrichment.enrich_candidate
     │                  ├─ spec_compiler.compile_skill_spec
     │                  └─ quality.compute_quality
     │              + approvals.apply_existing_statuses
     │              → candidates.json + report.md + analytics.json
     │
     ├──► render_skill (Jinja2 SKILL.md.j2 → SKILL.md)
     │      └─ 출력: <skills_dir>/<name>/SKILL.md (Claude Code frontmatter)
     │
     └──► dashboard.py → dashboard.html + dashboard.json
```

### 2.2 Key Design Decisions

| 결정 사항 | 선택 | 근거 |
|---|---|---|
| 패키지 구조 | `tools/claude-skill-factory/skill_factory/` | 참조 프로젝트와 동일 패턴, monorepo 분리 가능 |
| Python 버전 | `>=3.11` | `tomllib` 표준 라이브러리, `Literal` 등 |
| import 경로 | `skill_factory` (변경 없음) | 모듈명은 중립적, 도메인 로직 재사용 용이 |
| CLI entry | `claude-skill-factory = skill_factory.cli:app` | 명령어 충돌 회피 |
| 설정 파일 포맷 | JSON (`.claude/settings.json`) | Claude Code 표준, TOML 파싱 위험 제거 (참조 H5 해결) |
| Scope 타입 | `Literal["user", "project"]` | 참조 M9 해결, 정적 검증 |
| 저장소 네임스페이스 | `.claude/prompt-history/` (project scope) | Codex의 `.codex-prompt-history/` 분리에서 통합 — `.claude/` 하위 일관 정리 |
| Skill 출력 위치 | `<repo>/.claude/skills/<name>/SKILL.md` (project) · `~/.claude/skills/<name>/SKILL.md` (user) | Claude Code 공식 사양 |
| Settings.json 머지 | matcher 단위 dedup + `.bak` 백업 + atomic write | 참조 C2 해결 |
| `init --yes` 의미 | 실제 confirmation prompt skip | 참조 H1 해결 |
| `inbox` 기본 모드 | TTY 감지 자동 (sys.stdout.isatty()) | 참조 H3 해결 |
| `--project` 플래그 | 모든 명령에 일관 적용 | 참조 H4 해결 |
| `approve` 정책 | ignored 상태에서 approve 시 명시적 `--force` 필요 | 참조 H2 해결 |
| `generalization_safety` 공식 | evidence 길이 + 변수 슬롯 비율 + 키워드 특이도 가중 | 참조 M7 해결 (현 공식은 사실상 항상 80+) |
| Secret patterns | 기존 6종 + Claude API key (`sk-ant-...`) 추가 | Claude Code 환경 대응 |
| 핸들러 redaction | 단일 entry point (`redact_secrets`) | 중복 제거 + 회귀 테스트 단일화 |
| Jinja2 모드 | `StrictUndefined` 유지 | 누락 키 silent fail 방지 |
| 의존성 | `typer>=0.12 · rich>=13.7 · jinja2>=3.1` 만 | Local-first/Deterministic 원칙 (참조 동일) |

### 5.3 Rollback Strategy (롤백 전략)

## 6. Edge Cases & Risks (엣지 케이스 및 위험)

| 위험 요소 | 영향도 | 완화 방안 |
|---|---|---|
| Claude Code의 hook payload 스키마가 마이너 버전에서 변경 | 높음 | `raw_payload_keys` 기록 + payload 키 fallback chain 구축 (참조 J.3). doctor에 `payload schema check` 항목 추가 검토 |
| Claude Code 실행 환경이 git repo가 아닐 때 metadata 누락 | 중간 | graceful degrade — `git_branch=None`, `repo_root=None`. `find_repo_root`가 `.claude/`도 root indicator로 인정 (참조 J.4) |
| 사용자가 `~/.claude/settings.json`에 이미 복잡한 hooks 보유 | 높음 | `merge_hooks_config` matcher 단위 dedup + `.bak` 백업 + 사용자 hook 보존. E2E-3로 회귀 검증 |
| settings.json 파싱 실패 (사용자 수동 편집 손상) | 중간 | `init`에서 명확한 에러 메시지 + 백업본 안내. dry_run으로 변경 사항 미리 확인 가능 |
| jsonl 무한 성장 (참조 M3) | 중간 | v0.1.0에서는 미해결, 사용자에게 wc -l 확인 가이드 + v0.2.0 로드맵에 `rotate` 명령 (참조 S2) |
| 유사도 임계값 0.52 magic number (참조 J.9) | 낮음 | docs/skill_template_spec.md에 튜닝 가이드 + `--similarity-threshold` 노출 (이미 노출됨) |
| Claude API key 패턴 누락 시 leak | 매우 높음 | `sk-ant-...` 패턴 추가 + secret 회귀 테스트 (TC-8.4) 필수 |
| Hook 명령이 PATH에서 사라질 때 (가상환경 비활성 등) | 중간 | hook stdout exit 0 (Claude Code 워크플로우 보호), stderr에 명확 안내 |
| `paths` frontmatter 필드 미지원 Claude Code 버전 | 낮음 | 옵션으로만 출력 (default 누락) — 미지원 버전에서도 무시되도록 |
| Skill description+when_to_use 1536자 초과 | 중간 | render_skill에서 자동 truncation (TC-4.7로 검증) |
| `disable-model-invocation`을 사용자가 `true`로 원할 때 | 낮음 | candidate metadata에 `disable_auto_invocation` 옵션 받아 frontmatter 반영 (Phase 4 task 2 참고) |
| ruff/pytest 의존성 호환성 (Python 3.11+) | 낮음 | pyproject.toml `requires-python = ">=3.11"` 강제. CI는 별도 작업 |
